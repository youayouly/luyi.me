# AI 提示词模板

::: tip 用法
复制下面模板，把方括号换成你的实际情况。给 AI 的上下文越**可验证**（路径、命令、现象），越少编造。
:::

## 角色

你是 [领域：例如资深前端 / VuePress / DevOps / 数据库] 工程师。优先给出**可验证**的结论与**可执行**的步骤；不确定时明确写「假设 + 如何验证」，不要编造我本地才有的信息。

## 项目背景（必填，3～10 行）

- 技术栈：[语言 / 框架 / 版本，例如 VuePress 2 + theme-hope + Vite]
- 仓库/模块：[路径或子系统名称]
- 运行环境：[本地 / 线上 / Docker / Vercel 等]
- 相关入口：[关键文件路径、路由、脚本名]

## 目标（必填，1～3 条）

我最终想达成：[例如「线上 /article 正常渲染卡片」]

## 现象（必填，尽量客观）

- 期望：[应该怎样]
- 实际：[现在怎样]
- 范围：[仅线上坏 / 仅本地坏 / 都坏 / 间歇性]
- 复现：[最短步骤 1→2→3]
- 时间点：[大概从哪次改动/部署后开始]

## 我已做过的尝试（选填）

- [已试过的命令、配置、回滚、查日志等；没有就写「无」]

## 材料（选填，能贴就贴）

- 报错全文 / 堆栈：
- 相关配置片段（可打码 Key）：
- 浏览器控制台 / 网络请求 / 截图说明：

## 输出格式（建议 AI 按此回复）

1. **结论**：一句话说明最可能原因
2. **证据**：对应日志、代码或配置依据
3. **修复步骤**：按顺序、可复制命令
4. **验证方式**：改完后如何确认已好
5. **回滚**：若失败如何撤回

## 变体：新功能开发

```markdown
## 目标
新增 [功能名]，用户能 [完成什么动作]。

## 约束
- 不改动 [已有模块]
- 沿用 [现有组件/样式/路由约定]
- 需通过 `npm run build`

## 验收
- [ ] 桌面 / 移动端各测一遍
- [ ] 无新增 console error
```

## 变体：代码审查

```markdown
## 范围
请审查 [文件/PR 描述]，关注：正确性、回归风险、是否与现有 convention 一致。

## 不必做
- 不要求大规模重构
- 不要无关风格改动
```
